# Baton sample: Expo app with expo-dev-client

A minimal Expo SDK 57 app (RN 0.86) with `expo-dev-client`, to try Baton with Expo development builds on iOS and Android.

## Setup

```sh
npm install
```

That's all. `ios/` and `android/` aren't committed: they're generated by `expo prebuild`. `baton.config.ts` uses `app.build`, so the first Concert runs prebuild, `pod install` and `xcodebuild`, then caches the app by native fingerprint (`app.json`, native dependency versions; the generated `ios/` is excluded).

## Why `connect: 'devClient'`

The dev client's launcher ignores `RCT_jsLocation`, and it discovers any dev server on the network, so with several Stages it would offer all of them. Instead, Baton:

- starts Metro with `--localhost`, so other Stages' dev clients can't discover it
- writes device-level preferences: this Stage's Metro as the "most recently opened" app, and the dev menu's onboarding sheet and floating button turned off
- launches the app with `--initialUrl http://127.0.0.1:<port>`, with no deep link and so no iOS "Open in…?" prompt

Maestro's `launchApp` relaunches (including `clearState: true`) then load the same Stage.

### On Android

Each emulator's traffic goes through its own proxy in Baton, which sends `10.0.2.2:8081` to the Stage's Metro. So every Stage uses the same URL, and Baton:

- turns the dev menu's onboarding, floating button and launch-time menu off
- opens the dev launcher with `…://expo-development-client/?url=http://10.0.2.2:8081`, which makes it the launcher's most recent app

`clearState` wipes the launcher's memory, so `app.json` sets the `expo-dev-client` plugin's Android `defaultLaunchURL` to `http://10.0.2.2:8081`: a fresh launch then opens the Stage's bundle by itself.

## Run

```sh
baton perform smoke              # 2 Acts; the flows assert the visible marker matches EXPECTED_MARKER
baton perform smoke -p android   # the same on Android emulators
```

To prove each Stage serves its own code, copy this directory and change `MARKER` in `App.tsx` and `EXPECTED_MARKER` in the copy's `baton.config.ts`. Then run `baton perform smoke` in both directories at the same time.
